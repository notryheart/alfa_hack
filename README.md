# Кредитный кабинет / Smart Credit Cabinet

Русскоязычный интерактивный прототип общего рабочего пространства бизнеса и банка. React 19, TypeScript, Vite; Django / DRF / PostgreSQL — отдельный серверный каркас для следующего этапа.

## Запуск интерфейса

Нужен Node.js 22.12+ (или актуальный Node 24) и npm.

```sh
npm ci
npm run dev
```

Откройте адрес Vite (по умолчанию `http://localhost:5173`). Главная `/` — публичная страница; `/login` — явно обозначенный демо-вход. Реальной регистрации и банковских подключений нет.

```sh
npm run build
npm run preview
npm test
npx playwright install chromium
npm run test:e2e
```

Если сборка `dist/` уже есть, её можно посмотреть и без Node:

```sh
python3 scripts/preview.py
# http://127.0.0.1:4173 — только локальный просмотр
```

Если просмотр уже запущен, просто откройте этот адрес: второй сервер не нужен.
Если порт занят другой программой, выберите свободный порт:

```sh
python3 scripts/preview.py --port 4174
# http://127.0.0.1:4174
```

В production настройте SPA fallback на `index.html` для всех клиентских путей, кроме `/api/*`. Пример — `nginx.example.conf`.

## Сценарий демонстрации

1. Нажмите **Открыть демо**, выберите **Я представляю бизнес**.
2. В обзоре откройте **Уточнить обороты по счетам**.
3. Загрузите тестовый PDF, PNG или JPG (до 20 МБ), отправьте комментарий. Запрос останется открытым, новая версия будет на проверке.
4. Через **Сменить роль** войдите как сотрудник банка. Из очереди откройте новую версию, оставьте замечание или примите её.
5. Вернитесь в запрос и отдельно нажмите **Отметить решённым**. Кнопка доступна только после принятия текущих версий связанных документов.
6. Посмотрите историю и вернитесь к роли клиента: данные одной демо-сессии общие.

Дополнительно: заявка → документы → бухгалтерская отчётность → версии 1 и 2 показывает исправление и принятие. Можно создать новый запрос банка, сохранить/отправить черновик заявки, искать и фильтровать материалы, прочитать уведомления.

Все данные **синтетические**. Изменения и метаданные сохраняются в `sessionStorage` текущей вкладки; байты загруженных файлов — только в памяти. После обновления загруженный оригинал недоступен, что явно обозначено в просмотре. Выход или **Настройки → Сбросить демо** восстанавливает пример. Не загружайте конфиденциальные документы.

## Структура

- `src/Landing.tsx` — оригинальная публичная страница и иллюстрации интерфейса.
- `src/App.tsx` — маршруты, демо-вход, оболочка и guards.
- `src/pages.tsx` — обзор, список и трёхшаговый мастер.
- `src/Workspace.tsx` — вкладки заявки, запросы, версии, обсуждения, проверка.
- `src/domain.ts`, `src/seed.ts`, `src/store.tsx` — типы, синтетические данные, единые правила изменений.
- `src/api.ts` — неактивная граница будущего API; DTO требуют согласования со схемой.
- `backend/` — Django/DRF-каркас с PostgreSQL-настройками, liveness и fail-closed заглушкой API.
- `docs/backend-contract.md` — инварианты, предложения API, необходимые проверки схемы и ограничения.

## Django-каркас (не нужен для демо)

SQL-схема не предоставлена. Доменные таблицы и миграции намеренно не создавались. Сервер **не реализует** бизнес-API: анонимным запросам запрещён доступ, авторизованные получают `501`. `/api/health/` не подтверждает готовность БД.

```sh
python3 -m venv .venv
. .venv/bin/activate
pip install -r backend/requirements.txt
export DJANGO_SECRET_KEY="$(python3 -c 'import secrets; print(secrets.token_urlsafe(48))')"
export DJANGO_DEBUG=true
python backend/manage.py check
python backend/manage.py test config
python backend/manage.py runserver
```

Ключ задаётся только через окружение, не записывается в репозиторий. PostgreSQL-параметры: `POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_HOST`, `POSTGRES_PORT`. Подключение и миграции следует выполнять после сопоставления существующего `schema.sql` и проверки прав доступа. Для production отдельно нужны реальные сессии/CSRF, file storage и quarantine, серверная авторизация каждого ресурса и действия, аудит и эксплуатационная конфигурация.

Внешний шрифт IBM Plex Sans/Mono опционален; при отсутствии сети используются системные fallback-шрифты. Видео, внешние изображения и сторонние UI-виджеты для первого рендера не требуются.
